# Optional Fullerenes agent tooling

Official source reviewed: https://github.com/codebreaker77/Fullerenes
Official Codex MCP configuration: https://developers.openai.com/codex/mcp

This is development tooling, independent of Python runtime dependencies and the
monitoring pipeline. Fullerenes CLI 0.1.4/core 0.1.2/daemon 0.1.4 were installed
under ignored `.runtime/agent-tools/`. Node 22.22.1 and npm 9.2.0 were available;
Commander requires Node >=20 and native better-sqlite3 may need build tools when
a matching prebuild is unavailable. The CLI package itself does not declare an
engine range. Python is supported through Tree-sitter; shell/YAML/dashboard JSON
are not indexed by this version. Its walker respects root .gitignore and skips
source files larger than 500 KiB.

## Install and index

These commands use a local prefix, not a global install or remote shell script:

```bash
npm install --prefix .runtime/agent-tools --cache .runtime/npm-cache --no-audit --no-fund --save-exact fullerenes@0.1.4
bash scripts/fullerenes.sh init .
bash scripts/fullerenes.sh query 'Where is MeasurementCollector implemented?' --budget 600
bash scripts/fullerenes.sh stats .
node scripts/verify_fullerenes.mjs
```

The installed local package-lock records resolved dependencies, but remains local.
The direct CLI is pinned; its transitive caret dependencies can change on a fresh
install. Preserve/review the local lock if exact tool reproducibility is needed.
Index data is `.fullerenes/graph.db` plus SQLite state. `index .` is incremental;
`watch .` upstream automatically refreshes and generates instructions; our
wrapper refuses it because it can overwrite user rules while running. Neither is needed
for monitoring to start. The wrapper uses the already installed package and
cannot silently download a new npx release.

## Project-only Codex integration

```bash
bash scripts/codex_fullerenes.sh mcp get fullerenes
bash scripts/codex_fullerenes.sh
```

The launcher passes documented `mcp_servers.fullerenes.command` and `args`
configuration overrides for a stdio server. It calculates absolute project paths,
changes to the repository root, and leaves user/global config untouched. The
repository .codex directory is read-only in this session, so no project config
was written there. For desktop clients, use the verified command `bash` and
arguments `/absolute/project/scripts/fullerenes.sh`, `mcp`, `/absolute/project`
in the client's supported MCP registration UI. The current running conversation
cannot hot-load these tools; start a session with the launcher to discover them.

Real protocol verification completed: initialization, nine tool definitions, and
`query_codebase` returned `src/monitoring/exporter.py`. The first sandbox handshake
closed; the same check outside the sandbox passed. CLI structural retrieval also
found MeasurementCollector and metrics_server. No model call or token comparison
was used, so no token savings are claimed. Codex is the actual current agent;
Antigravity was not available and its integration was not verified. The supported
fallback is CLI retrieval, rather than an invented Antigravity configuration.

## Generated files and limitations

`init` creates AGENTS.md, CLAUDE.md and `.cursor/rules/fullerenes.mdc`; the latter
two and the graph stay ignored. Maintain concise project rules in AGENTS.md.
Review changes after refresh: graph summaries and callers are heuristic and can
miss Python dynamic dispatch/import relationships. Generated prose is not proof
of implemented behavior or test success.

The official README describes preservation outside managed markers. Inspection
of the installed generator found exceptions: it clears existing text containing
`Auto-generated by Fullerenes` or `# Codebase context`, and overwrites the Cursor
rule directly. Back up/review instruction files before init/watch; avoid these
phrases in hand-authored instructions. A repeated refresh exposed another defect: marker text embedded in a generated
comment can cause handwritten rules to be erased on the next refresh. The wrapper
now snapshots all existing AGENTS.md, CLAUDE.md and Cursor rule files under
ignored `.runtime/`, restores their exact contents on exit after init/index, and
refuses watch. Repeated refresh checks verified identical instruction hashes.
AGENTS.md remains a concise handwritten file; backups and generated prose stay local.

Fullerenes stores source structure locally, but a connected agent can retrieve
source bodies into its own conversation. Exclude secrets before indexing;
review npm/native dependency supply-chain risks. Do not publish indexes,
private paths, node_modules or generated agent files. There is no repository
clone, submodule, remote shell script or global agent configuration change.
